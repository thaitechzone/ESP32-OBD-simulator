## 1. โปรเจกต์นี้คืออะไร

บอร์ด **ESP32 ธรรมดา (ESP32-WROOM-32 DevKit)** ทำตัวเป็น **อะแดปเตอร์ ELM327 แบบ Bluetooth Classic (SPP)** ที่ต่ออยู่กับ "รถจำลอง"
เพื่อให้เกจ **CYD (ESP32-2432S028)** หรือแอป OBD บนมือถือเชื่อมต่อและทดสอบได้ที่โต๊ะ โดยไม่ต้องออกไปที่รถจริง

```
┌──────────────┐   Bluetooth SPP    ┌─────────────────────────┐   WiFi / HTTP   ┌──────────────┐
│ เกจ CYD      │ ── ATZ, 010C ... ─▶│ ESP32 ตัวจำลอง           │◀──────────────▶│ มือถือ / คอม  │
│ (ผู้ถามค่า)   │◀─ 41 0C 0C 30 ──── │ ELM327 + รถจำลอง + เว็บ │  หน้าเว็บควบคุม │ (ผู้ควบคุม)   │
└──────────────┘                    └─────────────────────────┘                 └──────────────┘
                                         ▲ USB Serial 115200 (log + คำสั่งตัวอักษรเดียว)
                                         ▲ ปุ่ม BOOT (เปลี่ยนสถานการณ์) / LED GPIO2 (สถานะ)
```

ความสามารถหลัก

| ส่วน | รายละเอียด |
|---|---|
| ELM327 จำลอง | ชื่อ Bluetooth `OBDII` PIN `1234`, ตอบคำสั่ง AT และ OBD-II Mode 01 / 03 / 04 แบบ CAN 11 บิต (`A6`) |
| รถจำลอง | 9 สถานการณ์: เดินเบา, ขับในเมือง, 0-100, รอบแดง, น้ำร้อนเกิน, แบตต่ำ, น้ำมันใกล้หมด, ไม่รองรับ PID น้ำมัน, ปรับค่าเอง |
| หน้าเว็บควบคุม | `http://obd-sim.local` ดูค่าสด, เปลี่ยนสถานการณ์, แถบเลื่อน, รหัส DTC สูงสุด 8 รหัส, ปิด ECU, ปรับเวลาตอบ, ตัดลิงก์, ดู log |
| ควบคุมทางอื่น | คำสั่งตัวอักษรเดียวทาง USB Serial และปุ่ม BOOT |

## 3. วิธีใช้เอกสารนี้

มี 2 แบบให้เลือก

- **แบบ A — prompt แบบเต็ม (หัวข้อ 4):** วางครั้งเดียวได้โปรเจกต์ทั้งหมด เหมาะกับผู้ที่คุ้นเคยแล้ว แต่ตรวจและแก้ปัญหายากกว่า
- **แบบ B — prompt ทีละขั้น (หัวข้อ 5) แนะนำ:** สร้างทีละส่วน **upload และทดสอบให้ผ่านก่อน** แล้วค่อยไปขั้นถัดไป เข้าใจโค้ดมากกว่าและเจอปัญหาเร็วกว่า

ข้อปฏิบัติ

1. สร้างโฟลเดอร์ว่างแล้วเปิดใน VS Code ก่อนเริ่ม
2. วาง prompt ในกรอบโค้ดทั้งกรอบ (คัดลอกได้ด้วยปุ่มมุมขวาบนของกรอบ)
3. ข้อความใน `<...>` คือส่วนที่ผู้เรียนต้องแก้เอง เช่น `<COM7>`
4. อ่านโค้ดที่ AI สร้างทุกครั้ง ถ้าไม่เข้าใจตรงไหนให้ถาม AI ต่อ เช่น "อธิบายฟังก์ชัน mode01 ทีละบรรทัด"

## 4. Prompt แบบเต็ม (สั่งครั้งเดียว)

```text
ช่วยสร้างโปรเจกต์ PlatformIO ชื่อ "OBD2 ESP32 Simulator" ในโฟลเดอร์นี้
ให้บอร์ด ESP32 รุ่นดั้งเดิม (ESP32-WROOM-32 DevKit) ทำตัวเป็นอะแดปเตอร์ ELM327 แบบ Bluetooth Classic (SPP)
ที่ต่ออยู่กับรถจำลอง เพื่อให้เกจ OBD (ESP32 CYD) หรือแอปมือถือเชื่อมต่อทดสอบได้โดยไม่ต้องมีรถจริง
คอมเมนต์ในโค้ดและ README เขียนเป็นภาษาไทย ข้อความ log ใน Serial เป็นภาษาอังกฤษ

== โครงสร้างไฟล์ ==
- platformio.ini, src/main.cpp, include/web_page.h, include/secrets.h.example, .gitignore, README.md
- include/secrets.h (ไม่ขึ้น git) เก็บ WIFI_SSID / WIFI_PASSWORD; main.cpp ใช้ __has_include("secrets.h")
  ถ้าไม่มีไฟล์ให้ใช้ค่าว่าง

== platformio.ini ==
- env esp32dev, platform = espressif32@7.0.1 (Arduino core 2.0.17), framework arduino
- monitor_speed 115200, upload_speed 921600
- board_build.partitions = huge_app.csv (Bluetooth Classic ทำให้โปรแกรมใหญ่)
- build_flags -std=gnu++17 และ build_unflags -std=gnu++11

== การตั้งค่า (namespace cfg ใน main.cpp) ==
- ชื่อ Bluetooth "OBDII", PIN "1234", เวอร์ชัน "ELM327 v1.5"
- ปุ่ม BOOT = GPIO0 (debounce 40 ms), LED สถานะ = GPIO2
- ถ้าคอมไพล์บนชิปที่ไม่มี CONFIG_BT_ENABLED / CONFIG_BLUEDROID_ENABLED / CONFIG_BT_SPP_ENABLED ให้ #error เป็นภาษาไทย

== ELM327 ==
- รับคำสั่งทีละบรรทัด จบด้วย CR, ไม่สนตัวพิมพ์เล็ก/ใหญ่และช่องว่าง, ยาวสุด 32 ตัว (เกิน = ตอบ "?")
- CR เปล่า = ทำคำสั่งเดิมซ้ำ; ทุกคำตอบจบด้วย "\r\r>" (ถ้า ATL1 ใช้ "\r\n")
- echo เปิดเป็นค่าเริ่มต้นหลังรีเซ็ต/เชื่อมต่อใหม่
- หน่วงคำตอบแบบสุ่ม 20-50 ms (ปรับได้จากเว็บ 0-1000 ms), ATZ 400 ms,
  คำสั่ง OBD แรกหลัง ATZ/ATSP ตอบ "SEARCHING..." และหน่วงเพิ่ม 1500 ms
- คำสั่ง AT: ATZ/ATWS (รีเซ็ต ตอบเวอร์ชัน), ATI, AT@1 ("OBDII to RS232 Interpreter"), ATD,
  ATE/ATL/ATS/ATH/ATM 0|1, ATAT0-2, ATSPx, ATSTxx (ตอบ OK), ATDPN ("A6"),
  ATDP ("AUTO, ISO 15765-4 (CAN 11/500)"), ATRV (แรงดันแบต เช่น "14.1V"), อื่น ๆ ตอบ "?"
- ATS0 = ไม่มีช่องว่าง, ATH1 = ใส่ header "7E8" + ไบต์ความยาว
- Mode 01 (สูตรมาตรฐาน SAE J1979):
  0100 -> 41 00 18 1A 80 01 (รองรับ 04 05 0C 0D 0F 11 20)
  0120 -> 41 20 00 02 00 00 (รองรับ 2F) หรือ 00 00 00 00 ถ้าปิด PID น้ำมัน
  0101 -> ไบต์ A: bit7 = MIL, bit0-6 = จำนวนรหัส
  0104 โหลด / 0111 คันเร่ง / 012F น้ำมัน = A*100/255 %
  0105 น้ำหล่อเย็น / 010F อากาศเข้า = A-40 °C
  010C รอบ = (256A+B)/4, 010D ความเร็ว = A km/h
  PID อื่นหรือ Mode อื่น = "NO DATA"; รองรับตัวที่ 5 แบบ "010C1"
- Mode 03 แบบ CAN: "43 [จำนวน] [รหัสละ 2 ไบต์]"; ถ้าเกิน 2 รหัสให้ตอบหลายเฟรมแบบ ELM327 จริง
  (บรรทัดแรก = จำนวนไบต์ฐานสิบหก 3 หลัก, ต่อด้วย "0: ..." 6 ไบต์, "1: ..." 7 ไบต์ ...);
  ตอน ATH1 ตัดเหลือเฟรมเดียว
- Mode 04 ล้างรหัสทั้งหมด ตอบ "44"
- ECU ปิด: คำสั่ง OBD ทั้งหมดตอบ "NO DATA" (ถ้าเป็นการค้นหาครั้งแรกตอบ "UNABLE TO CONNECT"),
  ATRV ไม่เกิน 12.4 V

== รถจำลอง (อัปเดตทุก 50 ms) ==
ค่า: rpm, speed, coolant, throttle, load, intake, fuel, volt, gear; มีการแกว่งเล็กน้อย (jitter) ให้ดูเหมือนจริง
เกียร์ 1-6 อัตรา km/h ต่อ 1000 rpm = 7.5, 13, 20, 27, 34, 41 เลือกเกียร์ต่ำสุดที่รอบไม่เกินรอบเปลี่ยนเกียร์
สถานการณ์ (ตัวอักษร = คำสั่ง Serial, id = ชื่อใน API):
  i idle     เดินเบา 780 rpm, 0 km/h, น้ำ 90 °C, แบต 14.1 V, น้ำมัน 62 %
  c city     จอด 6 s -> เร่งถึงเป้า -> วิ่งคงที่ 10 s -> เบรก วนเป้า 40/60/30/50 km/h เปลี่ยนเกียร์ที่ 2600 rpm
  l launch   จอด 4 s -> คันเร่ง 100 % เร่งถึง 105 km/h (0-100 ประมาณ 6.7 s เปลี่ยนเกียร์ที่ 6200) -> ค้าง 3 s -> เบรก -> วน
             log เวลา 0-100 ที่ทำได้
  r redline  รอบขึ้นลง 3000 <-> 7200 ในเกียร์ 3 รอบละ 8 s
  o overheat เดินเบา น้ำขึ้น 0.6 °C/s ถึง 118 °C (สถานการณ์อื่นเย็นลง 1.5 °C/s กลับสู่ 90)
  b lowbatt  แบต 11.9 V
  f lowfuel  น้ำมัน 7 %
  n nofuel   ไม่รองรับ PID 2F (0120 ไม่มีบิต 2F, 012F ตอบ NO DATA)
  m manual   ทุกค่าตั้งจากหน้าเว็บ ไม่แกว่ง (เข้าโหมดนี้ให้คัดลอกค่าปัจจุบันเป็นค่าเริ่มต้น)
เมื่อเปลี่ยนการรองรับ PID น้ำมัน ให้ตัดลิงก์ Bluetooth อัตโนมัติ เพราะ CYD ถาม 0100/0120 แค่ตอนเชื่อมต่อ

== คำสั่ง Serial (ตัวอักษรเดียว ไม่ต้องกด Enter) และปุ่ม BOOT ==
- ตัวอักษรสถานการณ์ข้างบน, d = เปิด/ปิดรหัส P0133 + P0420, e = เปิด/ปิด ECU, x = ตัดลิงก์,
  s = พิมพ์สถานะ, h หรือ ? = ช่วยเหลือ
- ปุ่ม BOOT = วนไปสถานการณ์ถัดไป (ข้าม manual)
- พิมพ์สถานะสรุปทุก 5 วินาที และ log ทุกคำสั่งที่ได้รับพร้อมคำตอบ เช่น "[RX] 010C +27ms  410C0C30"

== LED GPIO2 ==
กะพริบเร็วตลอด = เปิด Bluetooth ไม่ได้, กะพริบช้า 0.5 s = รอเชื่อมต่อ,
ติดค้าง = เชื่อมต่อแล้ว (ดับแวบ 40 ms ทุกครั้งที่ได้รับคำสั่ง), กะพริบเร็ว 3 s = จับคู่ไม่สำเร็จ

== เครือข่าย ==
- ถ้ามี secrets.h ให้ต่อ WiFi บ้าน รอไม่เกิน 12 วินาที; ไม่ได้ให้เปิด AP "OBD-SIM" รหัส "obdsim1234"
- mDNS ชื่อ "obd-sim" (http://obd-sim.local), พิมพ์ IP ออก Serial ตอนบูต

GET  /                 หน้าเว็บ (เก็บใน PROGMEM ที่ include/web_page.h)
GET  /api/state        JSON: scenario, bt{ready,connected,peer,name,mac}, net{ap,ip,ssid}, uptime, cmds,

== หน้าเว็บ (HTML/CSS/JS ไฟล์เดียว ภาษาไทย ธีมมืด รองรับมือถือ) ==
- แถบบน: สถานะ Bluetooth + MAC ของ CYD, IP, จำนวนคำสั่งต่อวินาที
- การ์ดค่าสด: หน้าปัดรอบ (SVG โค้ง มีโซนแดง) + ความเร็ว + เกียร์, ช่องเล็ก COOL/BATT/FUEL/THR/LOAD/IAT
  สีตามเกณฑ์: น้ำ >= 105 แดง / >= 97 เหลือง, แบต < 12.4 แดง / < 12.8 เหลือง, น้ำมัน < 10 แดง / < 20 เหลือง
- การ์ดสถานการณ์ 9 แบบ แตะเพื่อเปลี่ยน
- การ์ด MANUAL: แถบเลื่อน 8 ค่า + ปุ่มค่าสำเร็จรูป (เดินเบา, ทางด่วน 110, เร่งสุด 6800, น้ำร้อน 110 °C, แบต 11.8 V, น้ำมัน 5 %)
- การ์ด DTC: ไฟ MIL, รหัสที่ใช้บ่อยแตะเพิ่ม/ลบ, ช่องพิมพ์รหัสเอง, ปุ่มล้าง
- การ์ดอะแดปเตอร์: สวิตช์ ECU, สวิตช์ PID น้ำมัน, แถบเวลาตอบต่ำสุด/สูงสุด, ปุ่มตัดลิงก์
- กล่อง log: ซ่อนการวนถามค่าได้, หยุดเลื่อน, ล้างหน้าจอ
- ดึง /api/state ทุก 1 s และ /api/log ทุก 1.5 s, หยุดดึงเมื่อแท็บถูกซ่อน
- ถ้าเรียก API ไม่ได้ ให้เข้าโหมด DEMO จำลองค่าในเบราว์เซอร์

== สถาปัตยกรรม (สำคัญ) ==
WiFi กับ Bluetooth ใช้วิทยุตัวเดียวกัน หน้าเว็บที่ส่งช้าจะหน่วงคำตอบจน CYD หลุด จึงต้อง:
- แยก FreeRTOS task "elm" (stack 6144, priority 3, core 1) รับคำสั่งและส่งคำตอบทาง Bluetooth
- loop() ทำงานรถจำลอง, เว็บ, Serial, ปุ่ม, LED
- ข้อมูลที่ใช้ร่วมกันป้องกันด้วย recursive mutex ผ่าน struct StateLock (RAII)
  handler ของเว็บถือ lock เฉพาะตอนอ่าน/เขียนข้อมูล ไม่ถือระหว่างส่งผ่าน WiFi
- เหตุการณ์จาก Bluetooth callback (SPP open/close, ผลการจับคู่) ให้ตั้ง flag แล้วไป log ใน loop()
- การตัดลิงก์จาก loop() ให้ตั้ง flag ให้ task "elm" ตัดหลังส่งคำตอบที่ค้างอยู่

ตาราง LED, หน้าเว็บ + API, ตารางสถานการณ์/คำสั่ง Serial, ตารางคำตอบ ELM327, ตัวอย่าง log, แก้ปัญหาเบื้องต้น
```

## 5. Prompt ทีละขั้น (แนะนำสำหรับผู้เรียน)

### ขั้นที่ 2 — ELM327: รับคำสั่งและตอบคำสั่ง AT

```text
เพิ่มส่วน ELM327 ใน main.cpp
- อ่านจาก SerialBT ทีละตัวอักษร เก็บจนเจอ CR, ไม่สนช่องว่าง/LF/อักขระควบคุม, แปลงเป็นตัวพิมพ์ใหญ่,
  ยาวสุด 32 ตัว (เกินให้ตอบ "?"), CR เปล่า = ทำคำสั่งเดิมซ้ำ
- สถานะ elm: echo (เริ่มต้นเปิด), linefeed, spaces, headers, searchPending
- ทุกคำตอบจบด้วยบรรทัดว่างและ '>' เช่น "OK\r\r>" (ถ้า ATL1 ใช้ "\r\n"), ถ้า echo เปิดให้ส่งคำสั่งกลับก่อน
- คำสั่ง AT: ATZ / ATWS (รีเซ็ตทุกค่า ตอบ "ELM327 v1.5"), ATI, AT@1 ("OBDII to RS232 Interpreter"),
  ATD, ATE0/1, ATL0/1, ATS0/1, ATH0/1, ATM0/1, ATAT0-2, ATSPx (ตั้ง searchPending), ATSTxx ตอบ OK,
  ATDPN ตอบ "A6", ATDP ตอบ "AUTO, ISO 15765-4 (CAN 11/500)", ATRV ตอบ "14.1V", อื่น ๆ ตอบ "?"
- หน่วงคำตอบแบบสุ่ม 20-50 ms (ATZ 400 ms) โดยไม่ใช้ delay() ค้าง: เก็บคำตอบไว้แล้วส่งเมื่อถึงเวลา
- เมื่อ client หลุดให้รีเซ็ตสถานะ elm
- log ทุกคำสั่งและคำตอบแบบอ่านง่าย เช่น "[RX] ATZ      +400ms  ELM327 v1.5"
build ให้ผ่าน
```

**ทดสอบ:** ใช้แอป Serial Bluetooth Terminal บน Android เชื่อม `OBDII` พิมพ์ `ATZ`, `ATI`, `ATRV`, `at sp 0` ดูคำตอบ

### ขั้นที่ 3 — รถจำลองและคำสั่ง OBD-II

```text
เพิ่มรถจำลองและคำสั่ง OBD-II
- struct Vehicle: rpm, speed, coolant, throttle, load, intake, fuel, volt, gear (ค่าเริ่มต้นเดินเบา 780 rpm)
- ฟังก์ชัน jitter() ให้ค่าแกว่งเล็กน้อย และ approach() ให้ค่าค่อย ๆ เข้าหาเป้าหมาย
- อัปเดตรถทุก 50 ms ใน loop()
- คำสั่ง OBD (เลขฐานสิบหก ความยาวคู่ หรือ 5 ตัวแบบ "010C1"; ผิดรูปแบบตอบ "?")
  ครั้งแรกหลัง ATZ/ATSP ให้ขึ้น "SEARCHING..." และหน่วงเพิ่ม 1500 ms
- Mode 01:
  0100 -> 41 00 18 1A 80 01, 0120 -> 41 20 00 02 00 00, 0101 -> 41 01 00 07 E5 00
  0104 โหลด / 0111 คันเร่ง / 012F น้ำมัน = A*100/255 %
  0105 น้ำหล่อเย็น / 010F อากาศเข้า = A-40 °C
  010C รอบ = (256A+B)/4, 010D ความเร็ว = A km/h
  ค่าที่เกินช่วงให้ constrain ไว้; PID หรือ Mode อื่นตอบ "NO DATA"
- รองรับ ATS0 (ไม่มีช่องว่าง) และ ATH1 (header "7E8" + ไบต์ความยาว)
- ATRV ตอบแรงดันจาก car.volt
build ให้ผ่าน
```

**ทดสอบ:** ส่ง `ATZ` → `ATSP0` → `0100` (ต้องเห็น `SEARCHING...`) → `010C` → `ATS0` → `010C` เทียบผลกับสูตร

### ขั้นที่ 4 — สถานการณ์, รหัสข้อผิดพลาด, Serial, ปุ่ม, LED

```text
เพิ่มสถานการณ์การขับและการควบคุม
- enum Scenario และตาราง SCENARIOS {ตัวอักษร Serial, id, ชื่อ, คำอธิบาย} มี static_assert ว่าครบทุกตัว:
  i idle, c city, l launch, r redline, o overheat, b lowbatt, f lowfuel, n nofuel, m manual
- เกียร์ 1-6 อัตรา km/h ต่อ 1000 rpm = 7.5, 13, 20, 27, 34, 41 ฟังก์ชัน driveTrain(shiftRpm) เลือกเกียร์และคำนวณรอบ
- city: จอด 6 s -> เร่งถึงเป้า -> คงที่ 10 s -> เบรก วนเป้า 40/60/30/50 km/h เปลี่ยนเกียร์ 2600
- launch: จอด 4 s -> คันเร่ง 100 % ถึง 105 km/h เปลี่ยนเกียร์ 6200 (อัตราเร่งตามเกียร์ 17,15,12,9,7,5 km/h/s)
  ช่วงต่ำกว่า 12 km/h ให้รอบสูงแบบคลัตช์ลื่น -> ค้าง 3 s -> เบรก -> วน, log เวลา 0-100
- redline: รอบ 3000 <-> 7200 เกียร์ 3 รอบละ 8 s
- overheat: น้ำขึ้น 0.6 °C/s ถึง 118, สถานการณ์อื่นกลับสู่ 90 (ลง 1.5 °C/s)
- lowbatt 11.9 V, lowfuel 7 %, ปกติ 14.1 V และน้ำมัน 62 % ลดลงช้า ๆ ระหว่างขับ
- nofuel: 0120 ไม่มีบิต 2F และ 012F ตอบ NO DATA
- manual: ใช้ค่าจาก manualCar ไม่แกว่ง (เข้าโหมดนี้ให้คัดลอกค่าปัจจุบัน)
- รหัสข้อผิดพลาดสูงสุด 8 รหัส (uint16_t เช่น P0133 = 0x0133) มีรหัส = MIL ติดใน 0101
  Mode 03 แบบ CAN "43 [จำนวน] [รหัส]" เกิน 2 รหัสตอบหลายเฟรมแบบ ELM327 จริง
  ("00A" / "0: 43 04 ..." / "1: ...") ตอน ATH1 ตัดเหลือเฟรมเดียว; Mode 04 ล้างรหัส ตอบ "44"
- ECU on/off: ปิด = คำสั่ง OBD ตอบ NO DATA (ครั้งค้นหาแรกตอบ UNABLE TO CONNECT), ATRV ไม่เกิน 12.4 V
- เมื่อเปลี่ยนการรองรับ PID น้ำมันให้ตัดลิงก์ Bluetooth (CYD ถาม 0100/0120 แค่ตอนเชื่อมต่อ)
- คำสั่ง Serial ตัวอักษรเดียว: ตัวอักษรสถานการณ์, d เปิด/ปิด P0133+P0420, e ECU, x ตัดลิงก์,
  s สถานะ, h/? ช่วยเหลือ; พิมพ์สถานะสรุปทุก 5 วินาที
- ปุ่ม BOOT (GPIO0, debounce 40 ms) วนสถานการณ์ถัดไป ข้าม manual
- LED GPIO2: กะพริบเร็ว = Bluetooth เปิดไม่ได้, กะพริบช้า 0.5 s = รอเชื่อมต่อ,
  ติดค้าง = เชื่อมต่อ (ดับแวบ 40 ms เมื่อได้รับคำสั่ง), กะพริบเร็ว 3 s = จับคู่ไม่สำเร็จ
build ให้ผ่าน
```

**ทดสอบ:** พิมพ์ `c`, `l`, `r` ใน Serial Monitor แล้วพิมพ์ `s` ดูค่าเปลี่ยน, กด BOOT, ดู LED, ส่ง `03` หลังพิมพ์ `d`

### ขั้นที่ 5 — WiFi, mDNS และ Web API + แยก task

```text
เพิ่มเครือข่ายและ Web API
- include/secrets.h.example (คอมเมนต์ภาษาไทยบอกวิธีคัดลอกเป็น secrets.h) มี WIFI_SSID, WIFI_PASSWORD
  main.cpp ใช้ __has_include("secrets.h") ถ้าไม่มีให้ใช้ค่าว่าง และเพิ่ม include/secrets.h ใน .gitignore
- ต่อ WiFi บ้านไม่เกิน 12 วินาที ไม่ได้ให้เปิด AP "OBD-SIM" รหัส "obdsim1234"
  mDNS "obd-sim" และพิมพ์ URL ออก Serial
- WebServer พอร์ต 80:
  GET  /api/state  JSON ค่าทั้งหมด (scenario, bt, net, uptime, cmds, car, manual, faults, ecu, fuelPid, latMin, latMax)
  GET  /api/log?since=N&quiet=1  ring buffer 80 บรรทัด ส่งครั้งละไม่เกิน 30 บรรทัด ตอบ {next, lines}
       quiet=1 ไม่ส่งบรรทัดวนถามค่า (01xx ยกเว้น 0100/0101/0120 และ ATRV)
  POST /api/scenario id= / POST /api/manual rpm speed cool thr load iat fuel volt (จำกัดช่วงค่า)
  POST /api/faults codes=P0133,P0420 (P/C/B/U, ตัดตัวซ้ำ, สูงสุด 8, ผิดรูปแบบตอบ 400)
  POST /api/adapter ecu= fuel= latmin= latmax= (0-1000 ms) / POST /api/drop (ไม่มี client ตอบ 409)
  POST ทุกตัวต้องมี header "X-SIM: 1" ไม่งั้นตอบ 403
- ให้ฟังก์ชัน log เขียนทั้ง Serial และ ring buffer
- สำคัญ: WiFi กับ Bluetooth ใช้วิทยุร่วมกัน ให้ย้ายงานรับ/ตอบ Bluetooth ไป FreeRTOS task "elm"
  (stack 6144, priority 3, core 1) ส่วน loop() ทำรถจำลอง เว็บ Serial ปุ่ม LED
  ป้องกันข้อมูลที่ใช้ร่วมกันด้วย recursive mutex ผ่าน struct StateLock แบบ RAII
  handler เว็บถือ lock เฉพาะตอนอ่าน/เขียนข้อมูล ห้ามถือระหว่าง server.send()
  การตัดลิงก์จาก loop() ให้ตั้ง flag ให้ task "elm" ตัดหลังส่งคำตอบที่ค้างอยู่
build ให้ผ่าน
```

**ทดสอบ:** เปิด `http://obd-sim.local/api/state` ในเบราว์เซอร์ และลองสั่ง

```bash
curl -X POST -H "X-SIM: 1" -d "rpm=6800&speed=123&cool=108" http://obd-sim.local/api/manual
```

## 6. Prompt ช่วยทดสอบและแก้ปัญหา

**ตรวจโค้ดเทียบกับ spec**

```text
อ่าน src/main.cpp แล้วตรวจว่าคำตอบของ 0100, 0120, 0101, 010C, 010D, 0105, 012F, 03 (1, 2, 3 และ 8 รหัส), 04
ทั้งแบบ ATS0/ATS1 และ ATH0/ATH1 ถูกต้องตามมาตรฐาน ELM327 / SAE J1979 หรือไม่
ยกตัวอย่างคำตอบเป็นข้อความจริงที่ส่งออก (รวม \r และ >) ทีละคำสั่ง
```

**ตรวจเรื่อง thread / mutex**

```text
ตรวจว่าทุกตัวแปรที่ task "elm" กับ loop() ใช้ร่วมกันถูกป้องกันด้วย StateLock ครบหรือไม่
และไม่มีจุดไหนถือ lock ระหว่าง server.send() หรือ SerialBT.print() นานเกินจำเป็น
```

**แก้ปัญหา (วาง log ให้ AI ดู)**

```text
อาการ: <อธิบายอาการ เช่น CYD เชื่อมได้แต่หลุดทุก 10 วินาทีเมื่อเปิดหน้าเว็บ>
log จาก Serial ของตัวจำลอง:
<วาง log>
ช่วยหาสาเหตุจาก log และโค้ดก่อน ยังไม่ต้องแก้ อธิบายสมมติฐานและวิธีพิสูจน์
```

**ทดสอบอัตโนมัติจากคอม**

```text
เขียนสคริปต์ Python (ใช้ pyserial หรือ requests) ที่เรียก Web API เปลี่ยนสถานการณ์ทีละแบบ
รอ 5 วินาที แล้วอ่าน /api/state และพิมพ์ค่า rpm speed cool volt fuel ของแต่ละสถานการณ์เป็นตาราง
```

## 8. เคล็ดลับการเขียน prompt

- **บอกตัวเลขให้ชัด** เช่น ชื่อ Bluetooth, PIN, เวลาหน่วง, เกณฑ์สี AI จะไม่เดาค่าผิด
- **ล็อกเวอร์ชัน** (`espressif32@7.0.1`) เพื่อให้ทุกคนในห้องได้ผลเหมือนกัน
- **บอกเหตุผลของข้อจำกัด** เช่น "WiFi กับ Bluetooth ใช้วิทยุร่วมกัน จึงต้องแยก task" AI จะออกแบบได้ถูกทาง
- **สั่งทีละขั้นและทดสอบทุกขั้น** ถ้าพังจะรู้ทันทีว่าพังที่ส่วนไหน
- **ให้ AI อธิบายก่อนแก้** เวลาเจอบั๊ก ให้หาสาเหตุจาก log ก่อน ไม่ใช่เดาแก้ไปเรื่อย ๆ
- **ห้ามใส่รหัส WiFi จริงในไฟล์ที่ขึ้น git** ใช้ `secrets.h` ที่อยู่ใน `.gitignore` เสมอ
