# OBD2 ESP32 CYD — ตัวจำลองรถ + ELM327

เฟิร์มแวร์สำหรับ **ESP32 ตัวที่สอง** ที่ทำตัวเป็น **อะแดปเตอร์ ELM327 แบบ Bluetooth Classic (SPP)** ต่อกับ "รถจำลอง"
ให้เกจ CYD (เฟิร์มแวร์ใน `src/main.cpp` ของโปรเจกต์หลัก) เชื่อมต่อและทดสอบได้ที่โต๊ะ ไม่ต้องออกไปที่รถ

- ชื่อ Bluetooth `OBDII` รหัส `1234` ตรงกับค่าเริ่มต้นของ CYD (`app::DEFAULT_OBD_NAME` / `DEFAULT_OBD_PIN` ใน `include/app_config.h`)
- ตอบคำสั่ง AT และ OBD-II Mode 01 / 03 / 04 ครบทุกคำสั่งที่ CYD ใช้ ด้วยสูตรเดียวกับที่ CYD ถอดค่า (`decodePid()`)
- มีสถานการณ์ทดสอบ: เดินเบา, ขับในเมือง, 0-100, รอบแดง, ร้อนจัด, แบตอ่อน, น้ำมันใกล้หมด, ไม่รองรับ PID น้ำมัน และ **ปรับค่าเอง (MANUAL)**
- **หน้าเว็บควบคุม** (`http://obd-sim.local`): ดูค่าที่ส่งให้ CYD แบบสด, เปลี่ยนสถานการณ์, ปรับค่าเองด้วยแถบเลื่อน,
  เลือกรหัสข้อผิดพลาดได้สูงสุด 8 รหัส, จำลอง ECU ไม่ตอบ, เปิด/ปิด PID น้ำมัน, ปรับเวลาตอบ, ตัดลิงก์ และดู log คำสั่ง
- ควบคุมได้อีก 2 ทาง: คำสั่งตัวอักษรเดียวทาง USB Serial และปุ่ม **BOOT** บนบอร์ด
- log ทุกคำสั่งที่ได้รับและคำตอบที่ส่งกลับออก USB Serial (115200) และหน้าเว็บ

> **สถานะ:** ทดสอบกับ CYD จริงแล้ว (2026-10-21): CYD เชื่อมต่อผ่าน Bluetooth ได้ ขึ้น ONLINE และค่าที่แสดงตรงกับที่ตัวจำลองส่ง
> หน้าเว็บทดสอบบนบอร์ดจริงแล้ว: เปลี่ยนสถานการณ์, ค่า MANUAL (CYD อ่านได้ตรง), รหัส 4 รหัสแบบหลายเฟรม (CYD อ่านได้ครบ), ECU ไม่ตอบ

## Build และ Upload

โฟลเดอร์ `simulator/` เป็นโปรเจกต์ PlatformIO แยกจากโปรเจกต์หลัก (มี `platformio.ini` ของตัวเอง: env `esp32dev`, Arduino, พาร์ทิชัน `huge_app.csv`)

**VS Code:** เปิดโฟลเดอร์ `simulator/` เป็น workspace แยก (File → Open Folder) แล้วกด Build / Upload / Monitor ของ PlatformIO ตามปกติ

**Command line:**

```bash
cd simulator
```

```bash
pio run -t upload
```

```bash
pio device monitor -b 115200
```

ถ้าต่อทั้ง CYD และตัวจำลองไว้ที่คอมพิวเตอร์เครื่องเดียวกัน ให้ระบุพอร์ตเอง เช่น `pio run -t upload --upload-port COM7` และ `pio device monitor -p COM7 -b 115200`

ตอนเปิดเครื่องจะพิมพ์ MAC ของ Bluetooth ออกมา (ใช้พิมพ์ใส่ CYD แทนชื่อได้):

```
OBD2 ESP32 CYD -- ELM327 / vehicle simulator
[BT] slave "OBDII" PIN 1234, MAC 24:6F:28:xx:xx:xx
```

## จับคู่กับ CYD

1. เปิดตัวจำลองไว้ก่อน (เห็นบรรทัด `[BT] slave "OBDII" ...` ใน Serial Monitor)
2. บน CYD ไปหน้า **SET** (UI รุ่นเก่าคือ **CONFIG**) → แตะแถว **Adapter** → หน้า **SCAN** (ค้นหาประมาณ 10 วินาที)
3. เลือก **`OBDII`** (มีป้าย `OBD`) — CYD จะจำ MAC ไว้และเชื่อมตรงในครั้งต่อไป
4. PIN ใช้ค่าเริ่มต้น `1234` ไม่ต้องแก้
5. Serial ของตัวจำลองจะขึ้น `[BT] client connected` ตามด้วยคำสั่งเริ่มต้นของ CYD:
   `ATZ` → `ATE0` → `ATL0` → `ATS0` → `ATH0` → `ATAT1` → `ATSP0` → `0100` (SEARCHING...) → `ATDPN` → `0120` แล้ววนถามค่า

ถ้าชื่อ `OBDII` ตั้งไว้ใน CYD อยู่แล้ว (ค่าเริ่มต้น) CYD จะค้นหาด้วยชื่อแล้วเชื่อมเองได้ทันทีโดยไม่ต้องเข้าหน้า SCAN (แต่ช้ากว่าเชื่อมด้วย MAC)

> ESP32 กับ ESP32 อาจจับคู่แบบ SSP (Simple Secure Pairing) แทนการใช้ PIN ไลบรารี BluetoothSerial ยืนยันให้อัตโนมัติทั้งสองฝั่ง
> ผลการจับคู่ log เป็น `[BT] pairing ok` / `FAILED`

### LED สถานะ (GPIO2)

| LED | ความหมาย |
|---|---|
| ติดค้างสั้น ๆ ตอนเปิดเครื่อง | ทดสอบ LED ระหว่างเริ่ม Bluetooth |
| กะพริบช้า (ติด 0.5 วินาที / ดับ 0.5 วินาที) | Bluetooth พร้อม ค้นหาเจอได้ **รอ CYD เชื่อมต่อ** |
| ติดค้าง | **CYD เชื่อมต่ออยู่** ดับแวบสั้น ๆ ทุกครั้งที่ได้รับคำสั่ง (เห็นการวนถามค่าเป็นการกะพริบถี่ ๆ) |
| กะพริบเร็ว 3 วินาที แล้วกลับไปกะพริบช้า | จับคู่ (pairing) ไม่สำเร็จ |
| กะพริบเร็วตลอด (5 ครั้ง/วินาที) | เปิด Bluetooth ไม่ได้ ดู log `[BT] FAILED to start` |

Serial log ที่เกี่ยวข้อง: `[BT] SPP opened by <MAC>` (CYD เปิดช่อง SPP สำเร็จ), `[BT] client connected` / `disconnected`, `[BT] SPP closed`, `[BT] pairing ok` / `FAILED`

### API

หน้าเว็บเรียก API เหล่านี้ (ใช้จากสคริปต์ทดสอบอัตโนมัติได้) คำสั่ง `POST` ต้องมี header `X-SIM: 1`

| Endpoint | หน้าที่ |
|---|---|
| `GET /api/state` | สถานการณ์, สถานะ Bluetooth / WiFi, ค่ารถ, ค่า MANUAL, รหัส, การตั้งค่าอะแดปเตอร์ |
| `GET /api/log?since=N&quiet=1` | log ตั้งแต่บรรทัดที่ N ครั้งละไม่เกิน 30 บรรทัด (ตอบ `next` ไว้ถามครั้งถัดไป), `quiet=1` = ไม่รวมการวนถามค่า |
| `POST /api/scenario` | `id=idle / city / launch / redline / overheat / lowbatt / lowfuel / nofuel / manual` |
| `POST /api/manual` | `rpm speed cool thr load iat fuel volt` (ส่งเฉพาะค่าที่เปลี่ยน, สลับเป็น MANUAL ให้เอง) |
| `POST /api/faults` | `codes=P0133,P0420` (ว่าง = ไม่มีรหัส) |
| `POST /api/adapter` | `ecu=0/1`, `fuel=0/1`, `latmin=`, `latmax=` (ms) |
| `POST /api/drop` | ตัดลิงก์ Bluetooth |

```bash
curl -X POST -H "X-SIM: 1" -d "rpm=6800&speed=123&cool=108" http://obd-sim.local/api/manual
```

## สถานการณ์และคำสั่ง Serial

พิมพ์ตัวอักษรเดียวใน Serial Monitor (ไม่ต้องกด Enter ก็ได้) หรือกดปุ่ม **BOOT** เพื่อวนไปสถานการณ์ถัดไป

| คำสั่ง | สถานการณ์ | สิ่งที่ CYD ควรแสดง |
|---|---|---|
| `i` | **IDLE** (เริ่มต้น) — รอบ ~780, 0 km/h, น้ำหล่อเย็น 90 °C, แบต 14.1 V, น้ำมัน 62 % | ค่าปกติ นิ่ง ๆ |
| `c` | **CITY** — จอด 6 วินาที → เร่ง → วิ่งคงที่ 10 วินาที → เบรก วนเป้า 40 / 60 / 30 / 50 km/h เปลี่ยนเกียร์ที่ ~2600 รอบ | ความเร็ว/รอบ/คันเร่ง/โหลดขยับตลอด, ข้อมูลหน้า TRIP |
| `l` | **LAUNCH** — จอด 4 วินาที → คันเร่ง 100 % เร่งถึง 105 km/h (0-100 ประมาณ 6.7 วินาที, เปลี่ยนเกียร์ที่ 6200 รอบ) → ค้าง 3 วินาที → เบรก → วนใหม่ | ตัวจับเวลา 0-100, ไฟเปลี่ยนเกียร์ (ค่าเริ่มต้น 6000 รอบ) |
| `r` | **REDLINE** — รอบขึ้นลง 3000 ↔ 7200 ในเกียร์ 3 รอบละ 8 วินาที | ไฟเปลี่ยนเกียร์, โซนแดง, เสียงเตือนรอบสูง |
| `o` | **OVERHEAT** — เดินเบา น้ำหล่อเย็นขึ้นทีละ 0.6 °C/วินาที ถึง 118 °C | เหลืองที่ 97 °C, เตือนเต็มจอที่ ≥ 105 °C (เปลี่ยนสถานการณ์อื่นแล้วจะเย็นลงทีละ 1.5 °C/วินาที ไว้ทดสอบ hysteresis) |
| `b` | **LOW BATT** — เดินเบา แบตเตอรี่ 11.9 V | toast `BATTERY LOW` (< 12.2 V) |
| `f` | **LOW FUEL** — เดินเบา น้ำมัน 7 % | toast `FUEL LOW` (< 10 %) |
| `n` | **NO FUEL PID** — `0120` ไม่มีบิตของ PID 2F และ `012F` ตอบ `NO DATA` | ช่องน้ำมันแสดง `N/A` |
| `m` | **MANUAL** — ค่าตามที่ตั้งจากหน้าเว็บ (ไม่แกว่ง) | ตามค่าที่ตั้ง (ปุ่ม BOOT วนข้ามสถานการณ์นี้) |
| `d` | เปิด/ปิด **รหัสข้อผิดพลาด** P0133 + P0420 และไฟ MIL (เริ่มต้น = ปิด) เลือกรหัสอื่นได้จากหน้าเว็บ | หน้า FAULT อ่านได้ 2 รหัส, ลบ (Mode 04) แล้วรหัสหายและ MIL ดับ |
| `e` | เปิด/ปิด **ECU** (ปิด = คำสั่ง OBD ตอบ `NO DATA`, `ATRV` ไม่เกิน 12.4 V) | WAITING FOR ECU, ค่าเป็น `--` |
| `x` | ตัดลิงก์ Bluetooth | CYD ขึ้น OFFLINE แล้วเชื่อมใหม่เอง (ใช้ทดสอบการเชื่อมต่อใหม่) |
| `s` | พิมพ์สถานะรถจำลองตอนนี้ | — |
| `h` / `?` | แสดงรายการคำสั่ง | — |

หมายเหตุ:
- CYD ถาม PID ที่รองรับ (`0100` / `0120`) **เฉพาะตอนเชื่อมต่อ** ตัวจำลองจึง **ตัดลิงก์ให้อัตโนมัติ** เมื่อเข้าหรือออกจากสถานการณ์ `n` เพื่อให้ CYD เชื่อมใหม่และรู้ว่าไม่รองรับ PID น้ำมัน
- ทุก 5 วินาทีพิมพ์บรรทัด `[SIM]` สรุปสถานการณ์, สถานะลิงก์ และค่าทั้งหมด

## คำตอบ ELM327 ที่จำลองไว้

กติกาทั่วไปเหมือน ELM327 จริง:
- คำสั่งจบด้วย CR (`\r`) ไม่สนตัวพิมพ์เล็ก/ใหญ่และช่องว่าง (`at sp 0` = `ATSP0`) ส่ง CR เปล่า = ทำคำสั่งเดิมซ้ำ
- ทุกคำตอบจบด้วย `\r\r>` (ถ้า `ATL1` ใช้ `\r\n` แทน `\r`)
- **echo เปิด** หลังรีเซ็ต/เชื่อมต่อใหม่ จนกว่าจะได้ `ATE0`
- `ATS0` = ไม่มีช่องว่างในคำตอบ (`410C0C30`), `ATH1` = ใส่ header แบบ CAN 11 บิต (`7E8 04 41 0C 0C 30`)
- หน่วงคำตอบแบบสุ่ม 20-50 ms (ATZ ~400 ms, คำสั่ง OBD แรกหลัง ATZ/ATSP ~1.5 วินาที)

### คำสั่ง AT

| คำสั่ง | คำตอบ |
|---|---|
| `ATZ` / `ATWS` | `ELM327 v1.5` (รีเซ็ตการตั้งค่าทั้งหมด echo กลับมาเปิด) |
| `ATI` | `ELM327 v1.5` |
| `AT@1` | `OBDII to RS232 Interpreter` |
| `ATD` | `OK` (ค่าเริ่มต้น ยกเว้น echo) |

### OBD-II (ตัวอย่างเป็นแบบ `ATS1` เพื่ออ่านง่าย)

| คำสั่ง | ตัวอย่างคำตอบ | ความหมาย / สูตร (เหมือน `decodePid()` ของ CYD) |
|---|---|---|
| `0100` | `SEARCHING...` (ครั้งแรก) + `41 00 18 1A 80 01` | รองรับ PID 04 05 0C 0D 0F 11 และ 20 (มีช่วง 21-40) |
| `0120` | `41 20 00 02 00 00` | รองรับ PID 2F (สถานการณ์ `n` = `41 20 00 00 00 00`) |
| `0101` | `41 01 00 07 E5 00` / `41 01 82 07 E5 00` | ไบต์แรก bit7 = MIL, bit0-6 = จำนวนรหัส (สูงสุด 8) |
| `010C` | `41 0C 0C 30` | รอบ = (256·A + B) / 4 → 780 rpm |
| `010D` | `41 0D 3C` | ความเร็ว = A km/h |
| `0105` | `41 05 82` | น้ำหล่อเย็น = A − 40 °C |
| `0111` | `41 11 1F` | คันเร่ง = A × 100 / 255 % |
| `0104` | `41 04 36` | โหลด = A × 100 / 255 % |
| `010F` | `41 0F 4C` | อากาศเข้า = A − 40 °C |
| `012F` | `41 2F 9E` | น้ำมัน = A × 100 / 255 % (สถานการณ์ `n` = `NO DATA`) |
| PID อื่นของ Mode 01, Mode อื่น | `NO DATA` | |
| `03` | `43 00` / `43 02 01 33 04 20` | แบบ CAN มีไบต์จำนวนรหัส: P0133, P0420 |
| `03` (3 รหัสขึ้นไป) | `008` / `0: 43 03 01 33 04 20` / `1: C1 00` | หลายเฟรม: บรรทัดแรก = จำนวนไบต์ (ฐานสิบหก) แล้วเฟรมละ 6–7 ไบต์ (ตอน `ATH1` ตัดเหลือเฟรมเดียว) |

## แก้ปัญหาเบื้องต้น

| อาการ | ลองตรวจ |
|---|---|
| compile ขึ้น `#error ... Bluetooth Classic` | เลือกบอร์ดผิด ต้องเป็น ESP32 ดั้งเดิม ไม่ใช่ S3/C3 |
| LED กะพริบช้าตลอด แต่ CYD เชื่อมไม่ได้ | CYD ยังไม่ถึงตัวจำลองเลย: ดู Serial ของ CYD ว่า `connect failed` หรือไม่, เลือกจากหน้า SCAN (ได้ MAC) แทนการค้นหาด้วยชื่อ |
| CYD หา `OBDII` ไม่เจอในหน้า SCAN | ตัวจำลองยังไม่บูต / มีอุปกรณ์อื่นเชื่อมอยู่แล้ว (SPP รับได้ทีละเครื่อง) — กด RESCAN |
| เชื่อมแล้วหลุด / `pairing FAILED` | ลบการจับคู่เก่า: กด EN (reset) ทั้งสองบอร์ด แล้วเลือกจากหน้า SCAN ใหม่ |
| ช่องน้ำมันยังเป็น `--` แทน `N/A` ในสถานการณ์ `n` | ลิงก์ยังไม่ถูกตัด: พิมพ์ `x` หรือกดตัดลิงก์ในหน้าเว็บ ให้ CYD เชื่อมใหม่ |
| CYD หลุดบ่อยตอนเปิดหน้าเว็บ (เวอร์ชันก่อน) | ESP32 ใช้วิทยุ 2.4 GHz ตัวเดียวทั้ง WiFi และ Bluetooth: เวอร์ชันนี้แยกการตอบ CYD ไปไว้ใน task ของตัวเอง (สำคัญกว่าหน้าเว็บ) และหน้าเว็บถามข้อมูลห่างลง ทดสอบเปิด 2–3 เครื่องพร้อมกันแล้วไม่หลุด ถ้ายังหลุด ให้ปิดแท็บที่ไม่ได้ดู (แท็บที่ซ่อนอยู่จะหยุดถามเอง) |
| เปิดหน้าเว็บไม่ได้ | ดูบรรทัด `[NET]` ใน Serial ว่าได้ IP อะไร หรือเปิด AP `OBD-SIM`, มือถือ/คอมต้องอยู่ WiFi วงเดียวกับตัวจำลอง |
| upload ไม่ได้เพราะพอร์ตไม่ตรง | ระบุ `--upload-port` เอง (ดูชื่อพอร์ตด้วย `pio device list`) |

## ข้อจำกัดที่รู้อยู่

- จำลองเฉพาะ ECU เดียวแบบ CAN 11 บิต (`A6`) ไม่จำลอง K-line/J1850 หรือหลาย ECU ตอบพร้อมกัน
- รหัสข้อผิดพลาดสูงสุด 8 รหัส ตอน `ATH1` ตอบได้แค่เฟรมเดียว (2 รหัส)
- หน้าเว็บไม่มีรหัสผ่าน ใครอยู่ WiFi วงเดียวกันก็สั่งงานได้ (ตั้งใจใช้บนโต๊ะทดสอบ)
- คำสั่ง AT ที่ไม่ได้ระบุในตารางตอบ `?` ทั้งหมด
- ทดสอบกับ CYD จริงแล้วเฉพาะสถานการณ์เดินเบา (IDLE) และกรณีไม่รองรับ PID น้ำมัน สถานการณ์อื่นยังไม่ได้ดูบนจอจริงครบทุกแบบ
